## Encoder
위키피디아에서 인코딩에 대해 아래와 같이 설명하고 있다.  
  
>**인코딩**(encoding)은 컴퓨터를 이용해 영상 **·** 이미지 **·** 소리 데이터를 생성할 때 데이터의 양을 줄이기 위해 **데이터를 코드화하고 압축하는 것**
  
위의 정의를 보면 알 수 있듯이 인코더는 데이터를 압축하는 역할을 한다.
  
### · Encoder 예시
예를 들어, 8비트 데이터가 있고, 해당 데이터의 **1개의 비트만 1이고 나머지 비트는 모두 0이라는 규칙을 가진다고 가정**하자. 그리고 인코더는 **오른쪽을 기준으로 데이터에 존재하는 1의 위치를 반환하는 역할을 수행**한다고 가정한다.
<div align="center"><img src="encoding.png" /></div>
  
가정한 8비트 데이터는 위 사진과 같은 형태를 가질 것이다. 사진에서 주어진 **0010 0000**을 인코더에 넣으면 1이 오른쪽 기준으로 5번째에 있으므로 **101**을 반환할 것이다. 8비트 데이터는 0~7번째까지 있으므로 인코더를 통해 8비트 데이터를 3비트(7을 표현할 수 있는 최소 비트)로 압축할 수 있는것이다.  
인코더는 주어진 데이터의 패턴이나 규칙을 활용해, 정보 손실을 최소화하면서 데이터를 압축하는 역할을 수행하며 정보를 압축하는 방식은 하나로 정해진 것이 아니라, 여러 가지 방법이 존재할 수 있다.

## Decoder
디코더는 인코더가 압축한 데이터를 입력받아 원래의 데이터를 복원하는 역할을 수행한다.

### · 전통적인 Encoder와 Decoder의 한계점
위에서 설명했듯이, 인코더는 주어진 데이터의 패턴이나 규칙을 활용해 데이터를 압축하는 역할을 하며, 디코더는 이를 다시 복원하는 역할을 한다. 그러나 전통적인 방식에서는 이러한 패턴이나 규칙을 사람이 직접 정의하고, 인코딩과 디코딩 방식을 수동으로 설계해야 하기 때문에, 데이터가 복잡할 경우 이를 구현하는 것이 사실상 불가능한 상황도 발생한다.

## AutoEncoder
딥러닝에서 사용되는 신경망은 데이터의 복잡한 패턴과 규칙을 잘 학습하는 특징을 가졌다. 이 특징을 활용하기 위해 인코더와 디코더를 신경망으로 대체한 것이 바로 오토인코더이다.  
신경망을 인코더와 디코더로 사용함으로써, 자동적으로 패턴과 규칙을 학습하여 데이터를 적절하게 압축할 수 있게 해주고, 압축된 데이터를 다시 디코딩하여 원본 데이터로 복원할 수 있게 된다.

### · 수학적 기호 표기와 용어
· $x$: 입력 데이터  
· $z$: 압축된 데이터(latent vector)  
· $\hat{x}$: 복원된 데이터  
· Latent vector: 인코더를 통해 얻은 압축된 데이터를 뜻함  
· Latent space: latent vector $z$들이 분포하는 공간  
  
### · AutoEncoder의 생성 모델로서의 활용
<div align="center"><img src="autoencoder_schema.jpg" /></div>
<div align="center" class="gray-medium">출처 : https://blog.keras.io/building-autoencoders-in-keras.html</div>
만약 입력 데이터로 이미지를 사용한다면, 디코더는 복원 과정에서 이미지를 생성하게 된다. 즉, 오토인코더에 이미지를 넣어 학습시킨다면 디코더는 이미지를 생성하는 모델이 되는 것이다.
  
### · 생성 모델로서의 한계점
<div align="center"><img src="ae_latent_space.png" /></div>
  
생성 모델은 latent space에서 샘플링한 임의의 잠재 변수 $z$를 입력하더라도, 그럴듯한 데이터를 생성할 수 있어야 한다. 그러나 오토인코더는 각 데이터 $x$를 단 하나의 latent vector $z$에만 deterministic하게 매핑하기 때문에, latent space 대부분의 영역은 학습에 사용되지 않은 채 비어 있게 된다. 이로 인해 latent space에서 임의의 $z$를 샘플링해 디코더에 입력하면, 해당 $z$가 의미 있는 데이터와 대응되지 않아 무의미한 출력이 생성될 가능성이 높다. 또한 확률성을 반영하지 않는 구조이므로, 다양한 출력을 생성하기 어렵고 생성 결과의 다양성이 보장되지 않는다.
<div class="divider"></div>
  
## Variational AutoEncoder(VAE)
생성 모델로서 오토인코더의 단점인 deterministic한 특징을 보완하기 위해 확률적인 접근법을 도입하고, 임의의 $z$에 대해서도 의미있는 생성을 하기 위해 고안된 것이 VAE이다.
  
### · VAE의 방법론
1. 오토인코더의 인코더가 하나의 데이터를 하나의 latent vector $z$에 매핑하는 것과 달리, VAE의 인코더는 **하나의 데이터 $x$를 latent vector $z$의 확률 분포**에 매핑한다. 글로만 보면 이해가 어려울 수 있지만, 아래에 있는 **Latent vector $z$ 직관적 시각화**를 참고하면 쉽게 이해할 수 있다.
2. 오토인코더의 디코더가 하나의 latent vector $z$를 입력받으면 항상 고정된 데이터 $x$만을 생성하는 것과 달리, VAE의 디코더는 확률적인 방식으로 작동하여, **같은 $z$를 입력받더라도 그에 대응하는 확률 분포에서 $x$를 샘플링**해낸다. 즉, VAE 디코더의 생성 과정은 deterministic하지 않고 확률 분포에 의존하므로 생성 결과의 다양성이 높아진다.
  
### · VAE 인코더 직관적 시각화
<div align="center"><img src="vae.png" /></div>
<div align="center" class="gray-medium">분포의 평균에 가까울수록 진하게, 멀어질수록 연하게 표현하여 확률 밀도의 차이를 시각적으로 나타냄</div>
  
하나의 데이터를 $z$의 확률 분포에 매핑한다는 표현은 다소 추상적으로 느껴질 수 있지만, 위 그림을 통해 직관적으로 이해할 수 있다. VAE는, 하나의 데이터를 그림처럼 확률 분포 형태의 공간에 매핑하는 것이다. 이를 통해 latent space의 대부분 영역이 의미있는 데이터와 매핑 가능해진다. 따라서 latent space에서 임의의 $z$를 샘플링하여 디코더에 입력하더라도, 대부분의 경우 생성을 잘해낸다. 
  
### · 확률 분포로 본 VAE의 인코더와 디코더
지금까지 인코더와 디코더가 확률 분포를 다룬다고 설명했는데, 이를 수식으로 나타내면 아래와 같다.  
인코더는 $x$가 주어졌을 때 latent vector $z$의 확률 분포를 만들어내며, 이를 $q_{\phi}(z|x)$로 표현한다.  
디코더는 $z$가 주어졌을 때 데이터 $x$의 확률 분포를 만들어내며, 이를 $p_{\theta}(x|z)$로 나타낸다.
이는 **VAE의 방법론**에서 설명한 것들을 수식으로 표현한 것일 뿐이다.  
이제 재매개변수화 트릭에 대해서만 알아보고 VAE의 구조/학습/추론에 설명하겠다.  
  
>참고로, 구현 과정에선 인코더와 디코더가 실제로 직접 확률 분포 역할을 하진 않는다. 대신, 해당 분포의 모수(예: 평균과 분산)를 예측해주는 방식으로 간접적으로 확률 분포 역할을 한다. 이는 모수만 있어도 해당 확률 분포를 완전히 정의할 수 있기 때문이다.  
>예를 들어, $q_{\phi}(z|x)$가 가우시안 분포라고 가정하면, 인코더는 그 분포의 평균 $\mu$와 분산 $\sigma^2$을 출력하게 된다.
  
> 또한 디코더가  $p_{\theta}(x|z)$와 같은 확률 분포를 모델링한다고는 하지만, 실제 구현에서는 이 분포에서 직접 샘플링을 수행하지 않고, 대부분의 경우 예측된 평균값 $\mu_{\theta}$(만약 $p_{\theta}(x|z)$가 베르누이 분포면 $p$)을 복원된 $x$로 간주하는 방식을 택한다. 따라서 구현 시 디코더가 출력하는 모수를 이용하여 샘플링을 할지, 아니면 평균값만 사용할지 개발자가 선택하면 된다.
  
### · Reparameterization Trick
<div align="center"><img src="reparam_back.png" /></div>
<div align="center" class="gray-medium">"An Introduction to Variational AutoEncoders(2019)" - Kingma et al.</div>
  
우리가 모델을 학습시키기 위해선 역전파를 해야 한다. 인코더에서 디코더로 $z$를 넘겨주기 위해선 확률 분포로부터 $z$를 랜덤하게 샘플링해주어야 하는데, 이 과정은 deterministic하지 않기 때문에 역전파가 불가능하다. 그래서 이를 해결하기 위해 재매개변수화 트릭이란 걸 사용한다.
<div align="center"><img src="reparam.png" /></div>
<div align="center" class="gray-medium">가우시안 분포의 재매개변수화 트릭 수식</div>
재매개변수화 트릭은 위 수식처럼, 분포에서 직접 샘플링하는 게 아니라 간접적으로 샘플링을 하는 트릭이다. 이 트릭을 이용하면 랜덤 과정을 하는 노드가 역전파 과정에 직접 참여하지 않으므로 역전파가 가능해진다.(가장 위의 사진 참고)
  
### · VAE 구조와 학습
<div align="center"><img src="vae-pipeline.png" /></div>
  
VAE 학습 과정의 구조는 위와 같다. 인코더 파이프라인에선 신경망이 $q_{\phi}(z|x)$의 모수를 예측하고, 이를 가지고 재매개변수화 트릭을 이용하여 $z$를 샘플링한다. 이 $z$를 디코더 파이프라인이 받아 신경망으로 $p_{\theta}(x|z)$의 모수를 예측하여, 이를 가지고 $\hat{x}$를 샘플링하여 데이터를 생성하게 된다. 그런데 위에서 언급하였듯이 실제 구현에선 대부분 디코더가 확률 분포에 따라 샘플링하는 과정을 시행하진 않고, 단순히 예측된 평균 $\mu_{\theta}$ 값을 생성된 $x$로 취급하여 사용한다.  
그럼 VAE는 어떤 loss를 최소화해야 학습할 수 있을까? 이는 데이터 $x$에 대한 log-likelihood $\log p(x)$를 간접적으로 최대화함으로써 학습할 수 있는데, 밑의 ELBO파트에서 설명할 것이다.  
  
> 여기서 $q_{\phi}(z|x)$와 $p_{\theta}(x|z)$는 사전 정의되는 확률 분포이며 분포의 형태는 사람이 직접 정의한다. 사전 정의된 확률 분포의 형태에 따라 신경망이 출력값이 달라진다. 예를 들어, 사전 정의된 확률 분포의 형태가 가우시안 분포라고 가정하면, 신경망은 $\mu$와 $\sigma^2$을 출력할 것이고, 베르누이 분포라고 가정하면 $p$를 출력한다. 위 사진 속 구조는 사전 정의된 확률 분포 형태를 가우시안이라고 가정을 했을 때를 기준으로 하고 있다.
  
### · VAE 추론 과정
<div align="center"><img src="inference.png" /></div>
  
추론 과정에서는 $x$와 인코더가 주어지지 않고 데이터를 생성해야 한다. 따라서 prior $p(z)$에서 $z$를 샘플링하여 디코더에 입력하야 랜덤한 이미지를 생성하게 된다. 여기서 $p(z)$는 사람이 모수까지 직접 정의해주는 분포이며, 만약 $z$의 분포가 $\mu=0$이고 $\sigma^2=1$인 가우시안 분포를 따르게 하고 싶으면 $p(z) = \mathcal{N}(0,I)$처럼 정의하면 된다.  
여기서 한 가지 의문이 들 수 있다. 학습 과정에서는 $q_{\phi}(z|x)$에서 latent vector $z$를 샘플링하여 디코더를 통해 데이터를 복원했는데, 추론(생성) 과정에서는 갑자기 prior 분포인 $p(z)$에서 $z$를 샘플링하여 데이터를 생성하게 된다. "두 분포가 서로 다를 수 있는데, 이렇게 해도 과연 그럴듯한 데이터를 생성할 수 있을까?"라는 의문이 들 수 있다.  
결론부터 말하자면, 문제 없이 잘 생성할 수 있다. 그 이유는 아래에 설명해놓은 ELBO를 보면 알 수 있는데, 학습 과정에서 ELBO를 최적화하면서 $q_{\phi}(z|x)$가 $p(z)$에 가까워지도록 유도되기 때문이다. ELBO 수식의 두 번째 항인 KL divergence $D_{\mathrm{KL}}(q_{\phi}(z|x) | p(z))$를 최소화함으로써, 두 분포는 점점 비슷해지며, 그 결과 $p(z)$에서 샘플링해도 자연스럽게 학습된 디코더가 의미 있는 데이터를 생성할 수 있게 된다.
  
### · Variational Inference
<div align="center"><img src="bayes.png" /></div>
<div align="center" class="gray-medium">베이즈 정리</div>
  
베이즈 정리를 보면 likelihood $p(x|z)$ 또는 $p(z)$가 복잡하거나 $p(x) = \int p(x|z)p(z)dz$를 계산하기 힘든 경우, posterior $p(z|x)$를 계산하는 것은 사실상 불가능하다.  
따라서 우리는 계산이 쉬운 분포(예 : 가우시안 분포)를 따르는 $q(z)$를 새롭게 정의하고, 이를 true posterior $p(z|x)$에 가깝게 만드는 방식으로 학습시킨다. 이러한 접근 방식을 **변분추론**이라고 한다.  
VAE에서도 **posterior 분포를 근사하기 위해 변분 추론이 사용**된다.  
VAE에서 $x$가 주어졌을 때 $z$의 분포(true posterior)인 $p(z|x)$가 존재할 것이다. 하지만 이는 직접 계산하기 어렵기 때문에 인코더 신경망으로 정의된 근사 분포 $q_{\phi}(z|x)$를 이용한다.
  
### · ELBO
만약 우리가 이미지 $x$의 분포인 $p(x)$를 알 수 있으면 바로 이미지 $x$를 샘플링(생성)할 수 있을 것이다.  
따라서 우리의 목표는 이미지의 분포인 $p(x)$를 찾기 위해 log-likelihood $\log p(x)$를 maximize하는 것이라고 봐도 된다. 하지만 $p(x) = \int p(x|z)p(z)dz$에서 z에 대한 적분은 너무 복잡하기 때문에 계산이 불가능하다. 따라서 우리는 $p(x)$를 직접 다루는 대신, ELBO라는 우회 경로를 이용할 것이다.  
ELBO의 수식 유도 과정은 아래와 같다.

$\log p_{\theta}(x)$를 모두 전개하면 위와 같이 나오는데, 3번째 줄의 계산 가능한 항만 남겨둔 것이 **ELBO**이다. 3번째 줄의 계산 불가능한 항은 KL Divergence이므로 0 이상의 값을 가진다. 따라서 ELBO를 maximize하는 것은 곧 $\log p_{\theta}(x)$를 maximize하는 데 기여하며, 이는 VAE가 MLE를 우회적으로 수행하는 방법이다.  
ELBO의 첫 번째 항은 $p_{\theta}(x|z)$가 latent vector $z$ ~ $q_{\phi}(z|x)$를 입력받아 데이터를 얼마나 잘 복원해내는지 측정하는 항이므로 Reconstruction loss라고 불리고, 두 번째 항은 $q_{\phi}(z|x)$가 우리가 사전에 정의한 prior 분포 $p(z)$에 가까워지도록 유도하여 latent space를 정규화하므로 Regularization loss라고 불린다.  
여기서 ELBO는 최대화 문제를 풀어야하는데, 우리는 loss와 같이 최소화하는 방법에 익숙하다. 따라서 ELBO를 최소화 문제로 수정하기 위해선 음수를 곱해주면 된다.  
  
>**Q. $p_{\theta}(x)$를 최대화하도록 학습했음에도 왜 VAE의 디코더는 $p_{\theta}(x|z)$로 데이터를 생성하는가?**<br>A. 학습 과정에서 VAE는 직접 계산이 불가능한 likelihood $p_{\theta}(x) = \int p_{\theta}(x|z)p(z)dz$를 대신하여, 이를 하한으로 근사한 ELBO를 최대화한다. 이 과정에서 포함된 reconstruction loss $\mathbb{E}_{{q}_{\phi}(z|x)}[\log p_{\theta}(x|z)]$은 디코더 $p_{\theta}(x|z)$가 주어진 latent vector $z$로부터 $x$를 정밀하게 복원하도록 유도한다.<br>따라서 학습이 완료된 후에는 $p_{\theta}(x)$ 자체가 명시적 형태로 존재하지 않기 때문에, 실제 데이터 생성을 위해서는 latent prior $p(z)$로부터 샘플링한 $z$를 입력하여 $x \sim p_{\theta}(x|z)$를 생성하는 방식으로 활용하게 된다.  즉, $p_{\theta}(x|z)$는 학습 중 보조 역할을 하면서도, 생성 시점에서는 실질적인 생성 모델로 작동한다.
  
  
## VAE 관련 추천 글
  
이 글을 작성하기 위해 VAE를 공부하던 중, 대부분의 설명글에서 **논리적인 모순**을 느꼈다.  
대표적인 예시는 다음과 같다:  
  
> "$p(x)$는 적분을 풀 수 없어 계산할 수 없다."  
> → 그런데 아무런 설명 없이 **갑자기 posterior $p(z|x)$가 등장**한다.
  
하지만 $p(z|x)$는 **조건부 확률의 정의상 분모에 $p(x)$가 있으므로**, 똑같이 계산 불가능하다.<br>그렇다면 대체 **왜 $p(z|x)$를 도입하는 걸까?**  
  
내 생각에 이 모순은 아래와 같은 전개 순서에서 비롯된 문제다.  
  
> 1 - 실제로는 **ELBO 유도 과정에서 $q_{\phi}(z|x)$를 도입**해 계산 가능하게 만들고,
> 2 - 그 결과로 $q_{\phi}(z|x)$가 **$p(z|x)$에 근사**된다는 결론이 나온다.
> 3 - 그런데 많은 설명 글이 이 과정을 생략하고, **갑자기 $p(z|x)$를 앞에 내세워버린다**.
  
이로 인해 설명 흐름이 명확하지 않고 모순이 있는 것처럼 느껴지게 된다.  
여기서 추가적으로  
  
> "$q_{\phi}(z|x)$는 왜 갑자기 $p(z|x)$의 근사 분포가 되는 거지?"  
> 와 같은 의문이 자연스럽게 들게 된다.  
  
대부분의 글은 이 문제를 **“변분 추론이니까 그렇다”는 식으로 간단히 넘기지만**,  
사실 이는 **EM 알고리즘의 관점에서 바라보면 훨씬 더 자연스럽고 명확하게 이해**할 수 있다.  
아래에 링크해둔 EM 알고리즘 글을 보고 VAE 수식들을 되짚어보면 큰 도움이 될 것이다.
